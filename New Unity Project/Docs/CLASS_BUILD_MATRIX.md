# Class build matrix — full roster coverage

## Scope and status
User direction: ALL classes receive 3–4 recognizable base builds, with limited investment across paths.
Warrior Tank/DPS/Support and Druid Tank/Melee/Healer/Ranged are the user-specified examples.
All other path names and mechanics below are proposed designs, not approved canon or implemented kits.

Coverage includes the initial 12 classes in the Strong Class Identity pillar of PROJECT_MASTER.md and every additional class seed
in section 66. This produces 20 design entries and 61 base builds after grouping Rogue with
Assassin/Shadow Operative/Spy as one candidate family. This is a coverage matrix, not a decision to
ship 20 classes: the brief's up-to-15 roster target and unresolved merges remain open.
The user's newer 3–4-build direction supersedes the brief's older up-to-3-specialization limit.

Novels have not been cross-checked. All proposed disciplines, forms, resources and signature mechanics
are PROVISIONAL/GAME-ONLY. Names appearing in the brief are not independently verified canon.

## Build loops and tradeoffs
Tank means a proposed sustained group-tanking path. Support and control do not automatically qualify
as a tank or primary healer. Different DPS paths must change decisions, not only damage color.

|---|---|---|---|
| Warrior | Tank | Spend vigor on blocks, intercepts and threat; time defenses against enemy swings | Reduced offensive spending |
| Warrior | DPS | Build weapon pressure and spend it during exposed-target windows | Fewer defensive responses |
| Warrior | Support | Rally allies and expose enemies; intercept at the right moment | Personal damage funds party gains |
| Paladin | Oathguard / tank | Maintain a defensive oath; convert fulfilled conditions into protection | Breaking formation loses momentum |
| Paladin | Judicator / melee | Mark a priority target and spend conviction on decisive strikes | Weak target switching and sustained group healing |

## Overlaps and roster decisions
- Warrior uses flexible weapon pressure; Knight uses explicit defensive commitments and duties; Paladin adds proposed restorative/oath magic. Keep all three only if those loops remain distinct in play.
- Rogue covers Assassin, Shadow Operative and Spy for planning. Spy/social progression may be a noncombat specialization; no separate class is assumed.
- Tinker emphasizes maintained constructs and reusable tools; Engineer emphasizes heavy ordnance and prepared terrain. If testing does not support that distinction, merge their best paths into one 3–4-path class.
- Cleric uses direct/ward casting; Healer uses prepared remedies and treatments. Their lore and class separation need validation.
- Shaman emphasizes anchors and weapon imbues; Windcaller emphasizes airflow, storm charge and movement. Avoid duplicate elemental caster kits.
- Necromancer manages renewable minion/essence networks; Warlock manages one pact and personal risk. Separate pets alone are insufficient differentiation.
- Alchemical Specialist remains conditional. If it becomes a profession, keep crafting/support there and move combat toxin ideas into Rogue or Healer paths instead of shipping a duplicate class.
- Druid remains the deliberate four-role generalist through different investments. Other classes do not automatically gain every role.
- Proposed tank paths: Warrior, Paladin, Druid, Monk, Knight (five candidates). Proposed primary-healing classes: Paladin, Cleric, Druid, Shaman, Necromancer, Bard, Healer (seven candidates). The latter exceeds the brief's 3–5 guideline across the combined candidate list; resolve during final roster selection, not by quietly calling support a healer.

## Shared tree contract
- One class tree contains 3–4 connected paths and a shared foundation. Branch labels guide builds; they do not lock out all cross-investment.
- Level unlocks supply a baseline kit. Talents change abilities, add defining actions, or alter resource interactions; basic class functionality must not depend on guessing a correct tree.
- Ranked nodes, prerequisite ranks, level gates and branch investment requirements control access. Branch thresholds count points in that branch, not unrelated paths.
- The finite point budget prevents taking every defining talent. Deep nodes reward commitment; occasional explicit exclusive choices stop incompatible mechanics.
- Every path needs an early defining modifier, a mid-tree interaction and a later signature choice. Numbers and total tree size remain balance work, not implemented promises.
- Hybrids must be viable alternatives, but should sacrifice peak role performance or defining talents. Avoid one mandatory cross-class pattern repeated throughout the roster.
- Tree UI shows connections, ranks, available/spent points, unmet requirements and the actual changed ability description.
- Allocation is a proposed transaction: validate the complete resulting tree before spending points or applying effects. Respec cannot leave orphaned nodes, invalid bars or leftover modifiers.
- Save stable class/node IDs and allocated ranks with an explicit schema migration. Never serialize tree screen positions as identity.
- For each build, validate solo viability, group contribution, resource pressure and behavior under interruption/movement. Compare hybrid output and utility against its opportunity cost.

## Delivery sequence and current implementation
The full matrix is documented now; coding every class at once is not implied by matrix coverage.
Shared class profiles, ownership/unlock gates, class-driven action bars and graph validation are implemented.
Only the reference Warrior kit is playable. No class has a playable talent tree yet.

1. Warrior Tank/DPS/Support slice: define actual nodes and abilities, then ship UI, effects, respec and save migration together.
2. Druid's four-role slice to prove different resources/forms and support targeting on the shared system.
3. Extend in coherent class batches from this full matrix, resolving overlaps before committing duplicate systems.
4. Validate build feel at meaningful milestones; automate routine technical checks.

The level-10 prototype samples build identity. Full endgame tree size, point cadence, capstones and final level cap remain to be designed.
